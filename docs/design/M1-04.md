# M1-04 · IPC protocol and the app shell — design brief

> The first screen of the product. Card: [`docs/specs/M1-sound/M1-04.md`](../specs/M1-sound/M1-04.md).
> Language: [`principles.md`](principles.md). Controls: [`../product/controls.md`](../product/controls.md).
> The implementation follows this brief; `ui-quality-reviewer` and `usability-reviewer` check the
> result against the numbers in **Measurements**.

## Job

**Open the app, see what is loaded, press play, hear it at a level that is not too loud, and know
where in the music you are.** Flows: **F0** (set up the sound) and **F1** (first run → music).

Three controls from `principles.md › Controls we will keep needing` are born here — **Transport**,
**Volume**, **Readout** — plus the **Error strip**. Everything else (reference, prompt, timeline,
layers, cue, filter, energy) is M4–M5 and does not appear, not even greyed out.

## Layout

### Regions

Four, top to bottom, in one full-height flex column. Each region lays its content inside the same
**content column**: `width: min(100% - 2 × var(--space-6), 1200px); margin-inline: auto`.

| Region | Element | Job | Height |
|---|---|---|---|
| `header` | `<header>` | the document: name · tempo · key | 64 px, fixed |
| `notice` | `<div>` | the error strip, when there is one | 0 or auto |
| `stage` | `<main>` | the readout, the beat indicator, the transport, the status line | fills the rest |
| `output` | `<footer>` | volume · mute · output device | 88 px, fixed |

`stage` centres its content on both axes. `output` is pinned to the bottom and never scrolls away —
stop and mute are always reachable (`principles.md › What we do not do`).

### What changes with width

| | 1024 | 1440 | 1920 |
|---|---|---|---|
| content column | 960 px (fluid: viewport − 2 × 32) | 1200 px | 1200 px |
| side gutters | 32 px | 120 px | 360 px |
| readout size | `--text-8` | `--text-8` | `--text-8` |
| transport button size | identical | identical | identical |
| `output` row | one row | one row | one row |
| device `<select>` width | 220 px | 260 px | 260 px |
| volume slider track | 240 px | 240 px | 240 px |

**Nothing else moves.** The type scale is not responsive, the readout is not responsive, and the
controls keep the same pixel size at all three widths. Reason: the three `shot` states are compared
across widths, and a screen with one number and three controls has no reason to reflow. Above
1200 px the design spends the extra space on emptiness, which is what "a booth at night, not a
spreadsheet" buys.

Below 1024 the layout is not designed (`CLAUDE.md › Quality targets`: desktop only, no mobile).
The window opens at 1440 × 900 (`apps/desktop/src/main/window.ts`).

## Tokens

This card writes `apps/desktop/src/renderer/tokens.css`. The gate is that **nothing on screen sits
outside these values**. Tailwind v4 reads them through `@theme inline`, so a theme swap is a change
of custom properties on `:root`, not a rebuild:

```
:root { --ui-surface: #0D0F12; … }                       /* dark, the default */
@media (prefers-color-scheme: light) { :root { --ui-surface: #FBFBFC; … } }
[data-theme="dark"]  { --ui-surface: #0D0F12; … }        /* the Settings override, M1-04 ships the hook */
[data-theme="light"] { --ui-surface: #FBFBFC; … }
@theme inline { --color-surface: var(--ui-surface); … }
```

### Space — 4 px base, exactly as `principles.md`

`--space-1` 4 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-5` 24 · `--space-6` 32 ·
`--space-7` 48 · `--space-8` 64. No other spacing value appears anywhere.

### Radius

`--radius-1` 4 px (the slider track, the beat dots' container) · `--radius-2` 8 px (buttons, the
select, the error strip) · `--radius-3` 12 px (reserved for cards, M4). `--radius-pill` 9999 px,
only for the mute toggle and the slider thumb — and note that on a 40 px-tall element the effective
radius is 20 px, not 9999.

### Type

No font is bundled in M1 (see **Open questions**). Three roles, system stacks:

```
--font-body:    ui-sans-serif, system-ui, "Inter", "Helvetica Neue", Arial, sans-serif
--font-display: same stack as --font-body, distinguished by weight 600 and --tracking-tight
--font-mono:    ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace
--tracking-tight: -0.02em
```

Scale, ratio 1.25 from a 13 px floor (`principles.md`: no text under 13 px). Line height in
parentheses:

| Token | px | Used for |
|---|---|---|
| `--text-1` | 13 (18) | control labels ("Volume", "Output"), the strip's action |
| `--text-2` | 16 (24) | body, the status line, the select |
| `--text-3` | 20 (28) | the document name, transport button labels, the error title |
| `--text-4` | 25 (32) | the dB value |
| `--text-5` | 32 (40) | reserved |
| `--text-6` | 40 (48) | reserved |
| `--text-7` | 50 (56) | reserved |
| `--text-8` | 62 (64) | the `bar:beat` readout |

`font-variant-numeric: tabular-nums` on: the readout, the dB value, the BPM.

### Motion

`--duration-1` 120 ms · `--duration-2` 240 ms · `--ease-out` `cubic-bezier(0.16, 1, 0.3, 1)` ·
`--ease-in-out` `cubic-bezier(0.4, 0, 0.2, 1)`. `--duration-beat` is not a static token: it is
`60000 / bpm` ms, set on the beat indicator as an inline custom property from the score's tempo
(468.75 ms at 128 BPM).

### Nothing new proposed

Every role above already exists in `principles.md`. `--radius-pill`, `--tracking-tight` and the
type scale are the concrete values of roles that file names in words. No token is added.

## Components and states

Element ids below are the `data-testid` values the `shot` script measures.

### 1 · Header — `document-name`, `document-tempo`, `document-key`

Left: the document name, `--font-display`, `--text-3`, `--color-ink`. Right: `128 BPM` then a
separator `·` in `--color-line` then `A minor`, both `--text-2` `--color-muted`, the digits in
`--font-mono` with `tabular-nums`.

The score carries no name field (`packages/score/src/schema.ts`: `lineage.label` is optional).
Copy: `score.lineage?.label` when present, otherwise **"Example set"** — the words
`usability.md › The empty state is a state` already uses. Key copy: `"A minor"` — tonic then mode,
lower case mode, never `Am`.

| State | Header shows |
|---|---|
| loading (no `score:load` yet) | name `Loading the set…` in `--color-muted`; tempo and key each `—` |
| loaded | name · `128 BPM` · `A minor` |

### 2 · Readout — `readout`, `beat-indicator`

`--font-mono`, `--text-8`, `--color-ink`, `tabular-nums`, `--tracking-tight`.

Format: `bar` padded to two digits, a colon, `beat` — **one-based**, so a stopped transport reads
`01:1` and never `00:0`. The colon is `--color-muted`. The padding is what prevents the shift at
bar 10; `tabular-nums` alone does not, because the digit **count** changes.

The readout is driven by a `requestAnimationFrame` loop reading `engine.position()` in the
renderer — **not** by `transport:position`, which only fires once per bar and would freeze the beat
digit for a whole bar. IPC carries the bar to `main`; the screen reads the engine directly.

Beat indicator: `score.meter.beatsPerBar` dots (4) in a row under the readout. Each dot sits in a
fixed 16 px box; the dot is 8 px `--color-line` at rest and 14 px `--color-accent` on the current
beat, so the state is carried by size as well as colour. Transition `--duration-1` `--ease-out`.

| State | Readout | Dots |
|---|---|---|
| loading | `—:—` in `--color-muted` | all `--color-line`, no dot active |
| stopped | `01:1` in `--color-ink` | dot 1 active, static |
| playing | advancing | the current beat active |
| ended (16 bars over) | back to `01:1` | dot 1 active |

### 3 · Transport — `transport-play`, `transport-stop`

Two buttons, `--space-3` apart. Two, not one toggling button: `principles.md` says stop is
deliberate; a label that swaps between "Play" and "Stop" changes the button's width and moves the
primary target under the cursor; and when Pause arrives in M4 the group becomes Play/Pause + Stop
without moving anything.

**Play** — primary. `--color-accent` fill, `--color-accent-ink` label, `--radius-2`, height 56 px,
min-width 148 px, `--text-3`, a 20 px triangle glyph then the word `Play` with `--space-2` between.
**Stop** — secondary. Transparent fill, 1 px `--color-line` border, `--color-ink` label, same
height, min-width 132 px, a 20 px square glyph then the word `Stop`.

| State | Play | Stop |
|---|---|---|
| rest (stopped) | accent fill, enabled | `disabled`, label and border drop to `--color-line` |
| rest (playing) | `disabled`, fill drops to `--color-surface-2`, label to `--color-line` | enabled |
| hover | fill lightens by the theme's next step — dark `#FFC06B`, light `#8E4000`; Stop's border goes to `--color-ink` | same rule |
| focus | `outline: 2px solid var(--color-ink); outline-offset: 2px` | same |
| active (pressed) | `transform: translateY(1px)`, no colour change | same |
| disabled | as above, plus `cursor: default`; the **reason** is in `status-line`, never a bare dead button | same |
| loading | Play disabled, `status-line` reads `Waiting for the set.` | disabled |
| error | unchanged — an error never blocks the transport | unchanged |

The glyphs are inline SVG in `currentColor` inside `inline-flex items-center justify-center`;
they are decorative (`aria-hidden`), the word carries the name.

### 4 · Status line — `status-line`

One line of `--text-2` `--color-muted` under the transport, `--space-5` below it. It is the screen's
`aria-live="polite"` region and the place every "why is this disabled" sentence lives. Fixed
height (24 px) so nothing jumps when it changes.

| Situation | Copy |
|---|---|
| loading | `Waiting for the set.` |
| stopped, ready | `Ready. Press play.` |
| playing | `Playing · bar 3 of 16` |
| playing, muted | `Playing · bar 3 of 16 · muted` |
| ended | `The set reached the end.` |
| no output device | `No output device. Connect speakers or headphones.` |

While playing, the line is rewritten only when the **bar** changes, not every beat — a live region
updated 128 times a minute is unusable with a screen reader.

### 5 · Volume — `output-volume`, `output-volume-value`

A native `<input type="range">`, `min="-60"`, `max="0"`, `step="1"`, so arrows, `Home`, `End`,
`PageUp` and `PageDown` come from the platform and need no code. Label `Volume`, `--text-1`
`--color-muted`, to its left with `--space-3` between.

Track: 240 × 4 px, `--radius-1`, `--color-line`. Fill (left of the thumb): `--color-accent`.
Thumb: 16 px circle, `--color-ink`, with a 2 px `--color-surface-2` ring — the ring is what makes
the thumb legible against the accent fill, since `ink` on `accent` in dark is only 1.53:1 while
`ink` on `surface-2` is 15.13 and `accent` on `surface-2` is 9.88. The input's own box is 32 px
tall so the pointer target clears 24 px.

Value: `--font-mono`, `--text-4`, `--color-ink`, `tabular-nums`, fixed width 96 px, right-aligned.
Format `−12 dB` with a real minus sign (U+2212), integers only, and `−60 dB` renders as
`−∞ dB` — at the bottom of the range the output is silent and the number should say so.

- **First run: −12 dB.** Restore rule: on launch, the stored value is applied as
  `min(stored, lastApplied)` — the app never restores louder than it last was, per
  `usability.md › heuristic 3`. Stored in `app.getPath('userData')`, never in the document.
- **`0`–`9`** set the value to `−60 + 6n` dB: `0` → −60 (silent), `5` → −30, `9` → −6. The top of
  the range, 0 dB, is reachable only by dragging or by `End` — a stray number key can never jump
  the output to full.

| State | Look |
|---|---|
| rest | fill `--color-accent` |
| hover | thumb grows to 18 px, `--duration-1` |
| focus | ring `2px --color-ink` at `outline-offset: 2px` around the whole input box |
| dragging | the dB value stays visible and updates on every step — the number is the readout of the gesture |
| muted | fill drops to `--color-line`, the value stays at its dB number and the word `muted` appears in `status-line`; the slider stays enabled, so lowering it while muted and then unmuting is quiet, not loud |
| disabled | never — volume works even before the score arrives |

### 6 · Mute — `output-mute`

A `<button>` with `aria-pressed`, 40 px tall, `--radius-pill`, padding-inline `--space-4`,
a 16 px speaker glyph plus a word.

| State | Fill | Border | Label | Glyph |
|---|---|---|---|---|
| off (rest) | transparent | 1 px `--color-line` | `Mute` | speaker |
| off (hover) | `--color-surface-2` | `--color-ink` | `Mute` | speaker |
| on | `--color-signal-warn` | none | `Muted` | speaker with a slash |
| focus | unchanged fill | `outline: 2px solid var(--color-ink); outline-offset: 2px` | | |

The label text changes, so the state is never carried by colour alone. `aria-pressed="true"` when
muted. Muting does not stop the transport: `bar:beat` keeps advancing (the card's gate).

### 7 · Output device — `output-device`

A native `<select>`, 40 px tall, `--radius-2`, 1 px `--color-line`, `--color-surface-2`,
`--text-2`, width 260 px (220 at 1024), `text-overflow: ellipsis`. Label `Output`, `--text-1`
`--color-muted`, to its left. Native, not a custom popover: it inherits keyboard, screen-reader and
platform behaviour, and the popover traps listed in `CLAUDE.md › UI` do not apply.

First option is always `System default` with value `''`. Then one option per
`enumerateDevices()` entry of kind `audiooutput`. The chosen device's name is visible at rest in
the closed select — F0 requires the device in use to be on screen.

| State | Select shows | Beside it |
|---|---|---|
| names unavailable (no microphone permission — `enumerateDevices` returns default-only entries with empty labels) | `System default` alone | a text button `Show my devices`, `--text-1`, underlined; hint under it: `liminal needs permission to see your device names.` |
| names available | the full list, current one selected | nothing |
| no `audiooutput` at all | one `disabled` option `No output device` | Play is disabled and `status-line` gives the reason |
| the device disappears while playing | falls back to `System default` | the error strip appears; playback does not stop |
| switching | the selection applies at once (`setSinkId`); no confirmation, no restart | |
| focus | `outline: 2px solid var(--color-ink); outline-offset: 2px` | |

`Show my devices` calls `getUserMedia({ audio: true })`, re-enumerates, and stops the returned
tracks immediately. It is a button the person presses, never something the app does on load.

### 8 · Error strip — `error-strip`

Full content-column width, `--color-surface-2` background, a 3 px `--color-signal-error` rule on
the left edge, `--radius-2`, padding `--space-4`, `--space-4` below the header. Title `--text-3`
`--color-ink`; one action button (`--text-1`, outline, 32 px tall) and a dismiss `×` (32 × 32,
accessible name `Dismiss`). `role="alert"`.

It is never a modal and never covers the transport (`principles.md`). Copy, in the user's words,
mapped from `EngineErrorCode` (`packages/engine/src/errors.ts`):

| Cause | Title | Action |
|---|---|---|
| `invalid-score`, `automation-*`, `unknown-*`, `unsupported-fx` | `This set could not be played.` | `Try again` |
| `invalid-audio`, `context-in-use`, `context-not-offline` | `The audio engine could not start.` | `Try again` |
| the selected device vanished | `The output device is gone. Sound moved to the system default.` | `Choose a device` — moves focus to `output-device` |
| a channel payload fails its Zod schema in the preload | `Something the app sent was not understood, so it was not applied.` | none, dismiss only |

The raw code and message are never shown; they go to the console and to `main`'s log.

### What `completeness.md` asks for and this screen does not have

Said plainly, per the rule that a brief omitting a row says why:

- **"Anything that plays over time expects pause, what comes next, and elapsed."** No pause: it
  lands in M4 (`controls.md › Transport`). No "next" and no elapsed: there is nothing after the
  16-bar fixture in M1, and elapsed time has no consumer until the timeline (M5). The transport
  group is laid out so Pause slots between Play and Stop without moving them.
- **"Any list expects reorder, remove, an empty state."** The device `<select>` is a picker, not a
  list the person owns; there is nothing to reorder or remove. Its empty case is designed above.
- **"Settings: one place, grouped."** No Settings panel in M1. Theme follows the system, reduced
  motion follows the system, and the safe start volume is fixed at −12 dB. `tokens.css` ships the
  `[data-theme]` hook so the panel, when it arrives, changes nothing visual.
- **"Any decision the system makes expects a why."** M1 makes no decisions; the brain is M4.

## Motion

| What | Duration | Easing | Meaning |
|---|---|---|---|
| beat dot fill and size | `--duration-1` | `--ease-out` | the beat — the one thing tied to the music's clock |
| button hover fill, thumb growth | `--duration-1` | `--ease-out` | affordance |
| transport enabled ↔ disabled | `--duration-2` | `--ease-in-out` | a state change |
| error strip enter | `--duration-2` | `--ease-out` | opacity 0→1 and `translateY(-4px)`→0 |
| the readout digits | none | — | numbers never animate; they would smear |

`@media (prefers-reduced-motion: reduce)`: every transition above becomes `0s`. The beat dot still
changes which dot is filled — the bar tick becomes a static indicator, exactly as `principles.md`
requires — it simply changes without a transition.

## Keyboard and accessibility

### Focus order

`transport-play` → `transport-stop` → `output-volume` → `output-mute` → `output-device` →
(`Show my devices`, when present) → (`error-strip` action, then dismiss, when present).

The DOM order is `header` → `notice` → `stage` → `output`, so the strip's action comes before the
transport in the DOM. Do **not** reorder with `tabindex`; when the strip appears, move focus
nowhere (it is `role="alert"`, so it is announced) — an unasked focus jump while music plays is
worse than an extra Tab.

### The map

| Key | Does | Scope |
|---|---|---|
| `Space` | Play when stopped, Stop when playing | global |
| `M` | toggles mute | global |
| `↑` / `↓` | volume ±1 dB | global |
| `0`–`9` | volume to `−60 + 6n` dB | global |
| `Tab` / `Shift+Tab` | focus order above | native |
| `Home` / `End` | volume to −60 / 0 dB | slider focused (native) |
| `PageUp` / `PageDown` | volume ±6 dB | slider focused (native) |
| `Enter` / `Space` | activates the focused button | native |

Two traps the global handler must dodge, both of which pass every unit test while being broken on
screen:

1. **`Space` with a button focused fires twice** — the button's own activation and the global
   handler. The global handler returns early when `document.activeElement` is a `<button>`.
2. **`↑`/`↓` inside the device picker** would move the volume while the person is choosing a
   device. The global handler returns early when the event target is the `<select>` or the range
   input (the range's native behaviour is already ±1 dB).

`Space` calls `preventDefault()` so the window never scrolls.

### Names and roles

| Element | Accessible name | Notes |
|---|---|---|
| `readout` | `Position` | `aria-label`, value read as text; **not** a live region — announcing every beat is unusable |
| `beat-indicator` | — | `aria-hidden="true"`; the readout already carries the value |
| `transport-play` / `transport-stop` | `Play` / `Stop` | the visible word is the name |
| `output-volume` | `Volume` | `<label for>`; `aria-valuetext="minus 12 decibels"` so a screen reader does not read `-12` as a bare number |
| `output-mute` | `Mute` | `aria-pressed`; the label becomes `Muted` when on |
| `output-device` | `Output device` | `<label for>` |
| `status-line` | — | `aria-live="polite"`, `aria-atomic="true"`, updated on bar change and on state change only |
| `error-strip` | — | `role="alert"` |

Focus indicator everywhere: `outline: 2px solid var(--color-ink); outline-offset: 2px`. Its
adjacent colour is always a surface (the outline sits outside the control), so contrast is
16.66:1 in dark and 17.37:1 in light — well past the 3:1 of SC 1.4.11 and the change-of-contrast
of SC 2.4.11. Never `outline: none`.

No information by colour alone anywhere: mute has a word and a slashed glyph; the transport's
disabled state has a sentence in `status-line`; the beat dot changes size as well as colour; the
error strip has a title, not just a red rule.

## Open questions

1. **The document's name.** `Score` has no name field; `lineage.label` is optional and the fixture
   does not set it. Options: (a) render `lineage.label ?? "Example set"` — the brief's default,
   and the words `usability.md` already uses; (b) add a required `name` to the score schema —
   a change to `@liminal/score`, outside this card; (c) show the score `id`. Taking (a) unless
   told otherwise.
2. **Bundling a display face.** `principles.md` asks for "a display face with character for numbers
   that matter". M1 ships system stacks, so the readout is a system sans rather than a face chosen
   for its digits. Options: (a) stay on system stacks through M5 and revisit at packaging;
   (b) vendor a variable subset of an OFL face now (adds a licensed asset to the repo — an owner
   decision under process §15). Taking (a) for this card.
3. **Asking for the microphone permission to read device names.** The `Show my devices` button is
   the only honest way to fill the picker, but it does raise a microphone prompt on the product's
   first screen. Options: (a) the button, as designed; (b) no button — the picker offers only
   `System default` in M1 and the named list waits for a Settings panel; (c) ask on first launch
   with an explanation screen. Taking (a); it is opt-in, explained, and never automatic.
4. **`0`–`9` mapping.** `−60 + 6n` dB is chosen so no number key can jump to full output. The
   familiar alternative is percent-of-range, which makes `9` ≈ −6 dB and `0` = silence too, but
   invites `0` being read as "zero dB". Taking the dB formula and printing it in the map.
5. **Design review.** This screen is new. `docs/design/README.md` marks it `awaiting design: ok` —
   the owner's approval on the brief is awaited before the shell is built. A design canvas of the
   three states at 1440 can be published on request.
