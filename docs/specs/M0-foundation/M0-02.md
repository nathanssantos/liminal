## Context

The package table is in [architecture.md](../../architecture.md#packages-and-boundaries). Every
package is born with one real test, and the import boundary becomes a test — not a convention.

## What to do

- `packages/score`, `composition`, `engine`, `analysis`, `brain`, `conductor`, `protocol`: each
  with `package.json` (`@liminal/<name>`, `type: module`, `exports`), `tsconfig.json` extending
  the base, `src/index.ts`, `src/index.test.ts` with **one test exercising something real**
  (e.g. `score` already exports `PPQ = 960` and the test asserts it).
- `apps/desktop` with `electron-vite` (main, preload, renderer in React 19), opening an empty
  window titled "liminal". Tailwind 4 configured with an empty tokens file.
- `tools/boundaries.test.ts` (runs in the root Vitest): reads every `package.json` and fails any
  `dependencies`/`devDependencies` between `@liminal/*` packages outside the architecture table.
  One **negative** test case with a fictitious `package.json` proves it catches.

## Done when

- [ ] `pnpm -r test` runs ≥ 1 real test in each of the 7 packages and in the app — proof: Vitest output with names.
- [ ] the boundaries test passes on the current tree and **fails** the fictitious case — proof: both cases in the report.
- [ ] `pnpm --filter desktop dev` opens a "liminal" window — proof: screenshot at `evidence/M0-02/window.png`.
- [ ] `pnpm typecheck` passes at the root — proof: full output.

## Out of scope

Any product code in the packages. Skeleton and one test only.

## Risks and questions

- `electron-vite` × Vite 8 × Electron 42: versions checked on the day; if the newest pair does not
  fit, use `marketmind`'s pair and note it in `rules.md`.
