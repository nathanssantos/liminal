## Context

`tools/analyzer` is Python (ADR-0005). It is born with the same rigor as the TS side: strict
types, lint, tests — and the worker protocol already defined, even if it only answers `ping`.

## What to do

- `tools/pyproject.toml` — **one** `uv` project, Python 3.12, with two packages: `analyzer/` and
  `board/` (the latter empty until M0-06). Minimal deps (`numpy`); dev: `ruff`, `mypy --strict`,
  `pytest`.
- `analyzer/__main__.py`: worker mode — reads JSON lines on stdin, answers JSON lines; command
  `ping` → `{"ok": true, "version": "..."}`; unknown command → `{"error": ...}`.
- Root scripts: `pnpm check` also runs `uv run ruff check`, `uv run mypy`, `uv run pytest` —
  **full output**.

## Done when

- [ ] `echo '{"cmd":"ping"}' | uv run --directory tools python -m analyzer` answers `{"ok": true, ...}` — proof: output.
- [ ] an unknown command returns `{"error": ...}` and the process **does not die** — proof: test `worker keeps running after unknown command`.
- [ ] `ruff`, `mypy --strict` and `pytest` pass, inside `pnpm check` — proof: full output.

## Out of scope

`librosa`, `yt-dlp`, any analysis (M2).
