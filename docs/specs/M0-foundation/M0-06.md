## Context

ADR-0006: the `.md` spec is the source; the issue is a mirror that accepts writes. This is the
script that makes the mirror exist and stay current, in both directions (process §8). Contract
in [board.md](../cross-cutting/board.md).

## What to do

- `tools/board/sync.py` (the `board` package of the `uv` project in `tools/`): walks
  `docs/specs/**/M*-NN.md`, reads the frontmatter, and per card:
  - empty `issue` → creates the issue (title `M1-02 · Engine plays a score live`, body = the
    `.md` without frontmatter + link to the file), writes the number and body hash into the
    frontmatter, adds it to the board;
  - `issue` filled → updates title, body, labels (`area:*`, `spike`), milestone;
  - board status: `.md` missing any mandatory section → `Backlog`; complete → `Specified`;
    **never demotes** a more advanced status;
  - `Priority` and `Listening` from the frontmatter.
- **GitHub → md** (process §8): an issue whose body/title differs from the hash stored in
  `sync:` → writes into the `.md` and opens PR `docs/sync-<nº>` that merges by itself; an issue
  without a `.md` → creates a skeleton in `Backlog` under the milestone's folder (or the open
  one); a status moved by hand → respected and recorded (`sync.statusBy: human`); new comments →
  listed in the output.
- `--dry-run` prints the plan without writing. `--only M1` limits to a milestone.
- Repo from the `git remote`; board project by title; fields and options resolved by name on
  every run — no id in code or config.
- Workflow `sync-board.yml`: runs on push to `main` when `docs/specs/**` changes; commits the
  updated frontmatter with `[skip ci]`.
- Run once: creates the issues of M0, M1 and M2.

## Done when

- [ ] `--dry-run` lists every card in `docs/specs` with the right action (create/update) — proof: output.
- [ ] after running, every `.md` has `issue:` filled and every issue is on the board with the right Status, Priority, Milestone and Area — proof: `gh project item-list` and the frontmatter `git diff`.
- [ ] running again creates **no** duplicate and demotes **no** status — proof: test with a fake board fixture + a second real run with no diff.
- [ ] editing an issue body on GitHub and running the sync produces PR `docs/sync-<nº>` with the updated `.md` — proof: PR link and diff.
- [ ] creating an issue by hand (no `.md`) and running the sync creates the skeleton in `Backlog` — proof: new file and board item.
- [ ] moving a card by hand to `Backlog` and running the sync does **not** bring it back — proof: test + real run.
- [ ] `ruff`, `mypy --strict`, `pytest` cover the script — proof: output.

## Out of scope

Moving cards by code state — that is `board.queue` / `board.move` (M0-07).

## Risks and questions

- Projects v2 is GraphQL. `gh api graphql` does it; the script keeps the queries in one
  `.graphql` file per operation.
