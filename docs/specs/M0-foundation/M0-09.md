## Context

The loop commits, pushes, opens PRs and merges by itself. `main` must be unreachable outside a
PR with green CI, and the commit message must follow the convention with nobody watching.

## What to do

- `main` protection via `gh api`: PR required, status checks `node`, `python`, `desktop`
  required, branch up to date, no force push, no delete; **no** human approval required (the
  merge policy is the process's §3.6).
- `tools/commit-msg.sh` as a `commit-msg` hook installed by `pnpm install` (via `prepare`, no
  dependency): rejects a first line > 72 chars, without a Conventional type, or outside the
  imperative (short list of accepted prefixes).
- `pnpm check` ends with a one-line summary per tool and exit code ≠ 0 if any failed — no `&&`
  chain that stops at the first.

## Done when

- [ ] `git push origin main` directly is refused — proof: push output.
- [ ] a PR with red CI shows merge blocked — proof: screenshot.
- [ ] a commit with message `update stuff` is refused locally; `feat: add the gate` passes — proof: both outputs.
- [ ] `pnpm check` with one lint error and one type error reports **both** — proof: output.

## Out of scope

Commit signing; CODEOWNERS.
