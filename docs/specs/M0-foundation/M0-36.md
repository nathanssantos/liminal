## Context

Trying to write a test for the engine re-arming its end callback surfaced a question no document
answers: **what should happen when someone presses play after the set has ended?**

Today `ended` fires, the engine sets itself to not playing and stops the transport, but the
transport position stays at the end of the document. So:

- `stop()` returns early, because it is already stopped, and emits no `stopped`;
- `play()` starts the transport from the end, and the end callback it re-arms fires against a
  position already past it.

Nothing in `M1-02` mentions playing twice, so the engine was never asked to decide. Three readings:

1. **`play()` after `ended` starts the document again from bar 0.** It is what a play button means
   to a person. It makes `play()` mean "start", and the engine rewinds.
2. **`play()` after `ended` does nothing**, and starting again is `stop()` then `play()`. It keeps
   `play()` meaning "resume", and makes the caller say explicitly that it wants the top.
3. **The engine has no opinion**, and the conductor decides in M4, because an endless set never
   ends on its own.

Recommendation: **1**. The renderer in M1-04 has a play button and a person behind it, and the
other two make that button do nothing after the last bar.

Whatever the answer, the branch that re-arms the end callback has no test today, because writing
one requires knowing this.
