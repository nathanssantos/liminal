## Context

[score.md](../cross-cutting/score.md) is the spec. This card implements it in `@liminal/score`,
no audio, no I/O.

## What to do

- Zod schemas for `Score` and every subtype; inferred types exported; `PPQ`.
- `validate(score)` with E1–E9 as errors and W1–W4 as warnings, each with a stable code (`E2`,
  `W1`) and an English message citing the element id.
- `barToTick`, `tickToPosition`, `scoreLengthBars`, `scoreLengthTicks`, `sectionAt`.
- `createRng(seed)` xorshift32 with `next`, `int`, `pick`; `newId(rng)` deterministic ulid.
- `stringify` (sorted keys, 2 spaces) and `parse` (validates; error with path).
- Fixture `sixteenBars` exactly as the spec describes, exported from `@liminal/score/fixtures`.

## Done when

- [ ] every invariant E1–E9 has a test that **rejects** a deliberately broken document and cites the code — proof: 9 tests named `E1 …` to `E9 …`.
- [ ] every warning W1–W4 has a test — proof: 4 tests.
- [ ] `sixteenBars` passes `validate` with zero errors and zero warnings — proof: test.
- [ ] `parse(stringify(s))` deep-equals `s` for the fixture and for 100 documents generated with `createRng` — proof: round-trip test.
- [ ] `createRng(42)` yields the same 1000 numbers on two runs, and a different sequence from `createRng(43)` — proof: test.
- [ ] `tickToPosition(barToTick(b))` returns `{ bar: b, beat: 0, tick: 0 }` for 0 ≤ b < 1000 in 4/4, 3/4 and 7/8 — proof: test.
- [ ] `stringify` of the fixture, committed as `fixtures/sixteen-bars.json`, does not change between two runs — proof: test compares with the file.

## Out of scope

Transforms, generators, tempo map, `sampler`.

## Risks and questions

- Zod 4 changed the `z.discriminatedUnion` and error APIs relative to 3; read the installed
  version's docs, not memory.
