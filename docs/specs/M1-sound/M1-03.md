## Context

The soundcheck (two-clocks) depends on rendering offline faster than real time, and the plan's
principle 3 depends on the same document yielding the same audio.

## What to do

- `renderOffline({ score, sampleRate = 48000, createContext }) → { channels: Float32Array[], sampleRate, durationSec }`;
  `createContext` receives `(channels, length, sampleRate)` and returns an `OfflineAudioContext` —
  the caller decides whether it is Chromium or the polyfill.
- `encodeWav(channels, sampleRate) → Uint8Array` (16-bit PCM), no dependency.
- `measureBasic(channels) → { peak, rms, silent }` for tests — not the M2 measurement.
- Record in `measurements.md`: render time of the fixture in Node.
- Tests render only as far as they look (`rules.md › engine`): the fixture once, for duration and
  levels; two bars for determinism, the seed and the wav.

## Done when

- [ ] rendered duration = `scoreLengthTicks / PPQ × 60 / bpm` ± 1 sample — proof: test.
- [ ] two renders of the fixture in Node yield **identical** `Float32Array`s — proof: byte-for-byte test.
- [ ] a render with a different `seed` on the same document yields the same audio (the seed does not change notes already written) — proof: test.
- [ ] `peak ≤ 1.0` and `rms > 0.01` on the fixture — proof: test.
- [ ] `encodeWav` produces a valid RIFF header that `ffprobe` reads with the right duration — proof: test calls `ffprobe` if available, otherwise validates the header.
- [ ] the fixture renders in Node in under a third of its own duration — proof: line in `measurements.md`. (⚠️ The criterion first read "< 5 s on an M3 Pro". Measured on an M3 Pro: **6.6–6.9 s** for 30 s of audio, and the cost is the synthesis itself — 4 s of the fixture renders in 192 ms with notes and 48 ms without, so 5 s is not reachable in Node without changing the sound. What the product needs is `SOUNDCHECK_BUDGET`, a third of the deadline (`two-clocks.md`), and 0.22× real time clears it. The number the soundcheck actually runs on is Chromium's, measured in M1-05.)

## Out of scope

Chromium × Node comparison (M1-05). Spectral measurement (M2).

## Risks and questions

- If Tone.js schedules with a `Transport` over `OfflineAudioContext` such that a second run in the
  same process inherits state, the determinism test catches it — and the fix is one `Transport`
  per context, never a global `Tone.setContext`.
