## Context

The UI exists from the start — simple, but with tokens and the right boundaries. The engine lives
in the renderer; `main` sends the document and receives position. All over typed channels from
`@liminal/protocol`.

## What to do

- `@liminal/protocol`: channels `score:load` (main → renderer, `Score`), `transport:play`,
  `transport:stop` (renderer → main → renderer, because main is in command; in M1 main only
  echoes), `transport:position` (renderer → main, stream on every `bar`), `engine:error`,
  `output:volume` (renderer → main, persisted), `output:mute`, `output:device` (main → renderer:
  the device list and the chosen one; renderer → main: the choice). Each channel = name + Zod
  schema for input and output; helper `defineChannel`.
- **Output stage** in `@liminal/engine`: a gain node **after** the master limiter, outside the
  document and outside `renderOffline` — `setOutputGain(db)`, `setMuted(bool)`, `setSinkId(id)`
  (Chromium's `AudioContext.setSinkId`). The soundcheck and the export never see it
  (`docs/product/controls.md › Two kinds of control`).
- **Volume, mute and device on screen**, in the transport group, built from `@liminal/ui`
  (`Slider`, `Toggle`, `Select`, `Transport`, `Readout`, `ErrorStrip` — M1-07): a slider with the
  value in dB (`↑`/`↓`, `0`–`9`), a mute toggle (`M`), the output device with a picker. First run starts at the
  safe level (−12 dB); later runs restore the last value, never louder; both are local
  preferences in `app.getPath('userData')`, not in the document.
- `apps/desktop/src/preload`: exposes `window.liminal` with one function per channel, validating
  with Zod both ways; `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- `main`: on `ready`, loads `sixteenBars` and sends `score:load`; logs received positions.
- Design brief first (`ui-designer` → `docs/design/M1-04.md`): the shell's layout, the tokens that
  are born here (`tokens.css` follows `docs/design/principles.md`), the transport control and the
  position readout, states (stopped, playing, error), keyboard map. The implementation follows it.
- `renderer`: Zustand state (`score`, `transport: 'stopped'|'playing'`, `position`); screen with:
  document name, BPM, key, big `bar:beat`, Play/Stop button — composed from `@liminal/ui`; the
  tokens come from the package (`@liminal/ui/tokens.css`) and Tailwind reads them via `@theme`;
  no loose value on screen and no component restyled in the app.
- Playwright with Electron: opens the app, clicks Play, waits for `bar:beat` to change, clicks Stop.
- Screen infrastructure the process requires from here on: `dev` starts with
  `--remote-debugging-port=9222` (development only); script `shot <state>` in
  `apps/desktop/tools/shot.ts` using `_electron.launch`, with states `open`, `playing`,
  `stopped`, saving `evidence/<id>/<state>-<width>.png` + `.json` with `getBoundingClientRect`
  and `getComputedStyle` of the named elements; widths 1024 / 1440 / 1920.

## Done when

- [ ] calling a channel with a payload outside the schema throws in the preload, and the renderer shows the error — proof: preload unit test with Zod.
- [ ] the app opens and shows BPM 128 and "A minor" — proof: `evidence/M1-04/open-1440.png`.
- [ ] Play makes `bar:beat` advance; Stop freezes it — proof: Playwright, `evidence/M1-04/playing-1440.png`.
- [ ] `pnpm --filter desktop shot open` produces screenshot + measurements at the three widths, and Playwright attaches over CDP to the app in `dev` — proof: the 3 files and one `getComputedStyle` read through the connection.
- [ ] the first run starts at −12 dB; setting −30 dB, closing and reopening restores −30 dB; the value never restores louder than the last one — proof: Playwright across two launches + a unit test on the preference store.
- [ ] mute silences the output within one buffer while `bar:beat` keeps advancing; the soundcheck's `measureBasic` of the same score is identical with and without mute — proof: engine test comparing renders.
- [ ] the device picker lists the system's outputs and switching moves the sound (`setSinkId`) — proof: Playwright asserts the selected `sinkId`; **listening** on two devices is part of this card's `heard: ok`.
- [ ] `↑`/`↓`, `0`–`9`, `M` and `Space` operate volume, mute and transport without the mouse — proof: Playwright keyboard test.
- [ ] no colour, space or font outside the tokens in the renderer's CSS — proof: grep for `#`, `px` and `rem` outside `tokens.css` is empty.
- [ ] `security-auditor`: no `nodeIntegration`, no `remote`, CSP defined — proof: agent report with no blocking finding.
- [ ] **listening:** audio comes out of the app's speakers, not the terminal — proof: the human says "ok".

## Out of scope

Reference, prompts, timeline, filter, layers, cue (M4–M5, `docs/product/controls.md`). Packaging.

## Risks and questions

- Autoplay: Chromium requires a user gesture for `AudioContext.resume()`. The click on Play is the
  gesture; create the context **on click**, never on `mount`. Note it in `rules.md` if it bites.
