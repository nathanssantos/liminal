## Context

Two-clocks: the soundcheck runs the **same** engine in a second, hidden window, in the same
Chromium as playback. This card creates the window, the channel, and measures what the
architecture assumed.

## What to do

- `main` opens a hidden `BrowserWindow` (`show: false`) with a minimal renderer that only imports
  `@liminal/engine` and answers `render:offline`
  (`{ score, sampleRate } → { wavPath, durationSec, renderMs }`), writing the wav to
  `app.getPath('temp')/liminal/renders/<id>.wav`.
- Channel in `@liminal/protocol`.
- Development command `pnpm --filter desktop render:fixture` that requests the render and prints
  path and time.
- Measure and record in `measurements.md`: render time in Chromium; Chromium × Node difference in
  duration, peak and RMS of the fixture.

## Done when

- [ ] two `render:offline` of the fixture in Chromium yield **byte-identical** files — proof: Playwright with Electron comparing hashes.
- [ ] the Chromium wav and the Node wav have the same duration ± 1 sample and RMS within ±1 dB — proof: test; the real value goes to `measurements.md`.
- [ ] the hidden window never shows and does not block the main one during a render — proof: Playwright: the main window answers a click during the render.
- [ ] 16-bar render time in Chromium recorded — proof: line in `measurements.md`.

## Out of scope

Spectral `measure` (M2). Render queue (M4).

## Risks and questions

- `OfflineAudioContext` in a hidden window may be throttled by Chromium with the window in the
  background (`backgroundThrottling`). Turn it off in `webPreferences` and measure.
