## Context

The review step cost more than the implementation on M1-02 (`docs/memory/measurements.md`,
2026-09-06). Process §3.4½ now runs the review in two passes on one prepared worktree, with review
state the merge gate reads. This card builds the script behind it. Contract in
[board.md](../cross-cutting/board.md).

## What to do

- `board.review --prepare`: one detached worktree at HEAD under
  `/tmp/liminal-review/<branch>/<sha>/`, `pnpm install` from the store (offline first), reused while
  the head is unchanged; prints `reviewPath`, `head`, `reviewedHead`, `round`.
- `board.review --scratch`: a throwaway worktree at the same commit with its own install, for an
  agent that edits or reverts; prints its path; `--scratch --clean` removes them. A copy sharing the
  prepared tree's `node_modules` through a link was measured and dropped: pnpm reads the modules
  directory as invalid and asks to purge it, which would take the prepared tree's install with it,
  and the copy would share the prepared tree's git state. A fresh offline install costs about a
  second.
- `board.review --findings <file>`: writes a round's findings into the state, so the gate's blocking
  branch is reachable from the command line.
- `board.review --state`: `evidence/<id>/review.json` with rounds, heads, findings and their status;
  `--round-done [--deep]` records the reviewed (and deep-pass) head.
- `board.deliver --merge` refuses when the branch names an issue no spec claims, and when
  `review.json` has an open blocking finding or no deep pass on
  the final head (or on a head whose diff to it touches only files the deep pass did not measure —
  the list of measured paths is recorded by `--round-done --deep`).
- `board.check` accepts `--path <reviewPath>` so it runs on the prepared tree.

## Done when

- [ ] two `--prepare` calls on the same head reuse the worktree and skip the install, and a call on a new head drops the older one — proof: two tests with a fake `pnpm` recording calls; timings in `measurements.md`.
- [ ] a `--scratch` worktree has its own install and its own git state, and a revert in it does not touch the prepared tree — proof: test, plus the cost in `measurements.md`.
- [ ] `review.json` round-trips findings through open → fixed and records `deepPassHead` — proof: test.
- [ ] `board.deliver --merge` refuses with an open blocking finding, refuses without a deep pass on the final head, merges when the diff since the deep pass touches only unmeasured paths, lets a branch that names no issue through, and refuses one that names an issue no spec claims — proof: six tests, three of them on the gate rather than on the predicate.
- [ ] a full `/review` of a small change on the prepared tree costs less than 15 min of wall clock in the fast pass — proof: the next card's timings in `measurements.md`.

## Out of scope

Changing what the reviewers measure (the recipes in `rules.md › review` grow per card).

## Risks and questions

- `pnpm install --offline` fails when the store lacks a package; fall back to online once and note it.
