## Context

The UI will grow into the booth (M5) and the layer map; every screen needs the same controls
with the same accessibility. `docs/design/components.md` sets the rules: one package, Radix
Primitives for behaviour, our tokens for looks, audio controls ours, a story and a test per
component. M1-04 (the shell with volume, mute and device) is the first consumer, so this card
comes first — and it brings what M0-02 already built (the shell, `tokens.css` in the app) into the
system instead of leaving it beside it.

## What to do

- `packages/ui` (`@liminal/ui`): `package.json`, tsconfig from the base, Vitest with React
  Testing Library and `axe-core`, Storybook (Vite builder, `addon-a11y`) — versions checked on the
  day and recorded in `measurements.md`; the boundary table in `tools/boundaries.ts` gains `ui`
  (imports nothing internal; `apps/desktop` may import it).
- `src/tokens.css` **moved** from `apps/desktop` and filled from `docs/design/principles.md`
  (colour roles for both themes, space on 4 px, radius, type, motion); the app imports it from the
  package; nothing of the M0-02 shell keeps a local token or a local style.
- Components, each with API, states, story per state and per variant, test per behaviour rule:
  `Button`, `Toggle`, `Slider`, `Select` (wrapping `radix-ui`), `Readout`, `Transport`,
  `ErrorStrip`.
- Storybook that **exercises every variant and prop**: autodocs per component, an `argType` with
  a control for every prop, a named story per state and variant, `play` interaction tests for the
  keyboard contract, `addon-a11y`, the 1024/1440/1920 viewports. `pnpm --filter ui storybook` opens the
  catalogue, `pnpm --filter ui test:stories` runs the interaction tests alone, and `pnpm check`
  runs them with everything else.
- The M0-02 shell refactored to compose `Transport` and `Readout` from the package (M1-04 adds
  the rest).
- `docs/design/components.md` catalogue rows marked `M1-07` filled with the real props.
- A design brief first (`ui-designer` → `docs/design/M1-07.md`): the look of these seven, from
  the principles, with measurements.

## Done when

- [x] `pnpm --filter ui test` runs a test per component that exercises keyboard behaviour and passes `axe` with no violation — proof: Vitest output listing them.
- [x] `pnpm --filter ui storybook` opens and every component has an autodocs page, an `argType` per prop, and a named story per state and variant — proof: the story list, one screenshot per component at 1440 in `evidence/M1-07/`, and a check that no prop in the component's type is missing from `argTypes`.
- [x] the interaction tests run headless in `pnpm check` and cover the keyboard contract of every component — proof: their output.
- [x] `Slider` and `Select` are operable by keyboard alone (arrows, Home/End, type-ahead) — proof: RTL tests.
- [x] no loose colour, space or font in `packages/ui/src` outside `tokens.css`, and none left in `apps/desktop` — proof: grep empty in both.
- [x] the boundary test knows `ui` and fails a fictitious `ui → engine` import — proof: test.
- [x] `apps/desktop` renders `Transport` and `Readout` from the package and `tokens.css` no longer exists in the app — proof: `shot open` at the three widths and the file listing.
